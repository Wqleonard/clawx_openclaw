# TOOLS.md - Local Notes

Skills define _how_ tools work. This file is for _your_ specifics — the stuff that's unique to your setup and the 短剧剧本文件规范。

## What Goes Here

- 短剧题材、目标平台、受众偏好等本地备注
- 常用集数区间、时长约束
- 任何与环境或项目相关的备忘

---

## 短剧文件结构规范

短剧相关文件直接暴露在根目录，不再额外包裹项目文件夹。文件名书写时在开头添加 `/` 表示根目录。

```
/剧情.md                  # 小说原剧情拆解或短剧剧情基础文本（可选）
/集纲.md                  # 短剧集纲（每集标题+梗概，起承转合完整）
/设定/                    # 短剧设定目录
/设定/剧本选题.md         # 剧本选题与基础信息（如有）
/设定/故事设定.md         # 故事设定（剧名、核心梗概、背景、亮点、信息差）（必须生成）
/设定/角色设定.md         # 角色设定（角色卡、人物标签、人物小传）（必须生成）
/剧本/                    # 剧本正文目录
/剧本/第1集.md            # 第1集剧本正文
/剧本/第2集.md            # 第N集剧本正文
```

- 初始状态可能仅包含部分空文件，也可能不存在任何文件；文件随短剧创作流程逐步创建与填充。
- 虚拟文件系统中文件与目录均使用中文命名，需带根路径 `/`，所有文件须含正确后缀（如 `.md`）。

## Markdown 文件格式规范

所有 `.md` 文件须遵守：

1. 遵循 CommonMark 规范。
2. 禁止行尾空格。
3. 禁止 HTML 段落标签（如 `<p></p>`）。
4. 分段使用连续空行（`\n\n`）。

## 技能系统与调用顺序

`writer` 子代理会按需读取技能文件；主 Agent 负责判断任务类型并正确委派。一般顺序：

| 顺序 | 技能 | 适用场景 |
|------|------|----------|
| 1 | `script-plot-skill` | 根据小说原文生成剧情拆解 → `/剧情.md`（按章节数，一章一拆） |
| 2 | `script-tag-skill` | 根据剧情生成标签与梗概 → `/设定/剧本选题.md` |
| 3 | `script-story-setting-skill` | 根据用户选择（原版/改编）及改写方向 → `/设定/故事设定.md` |
| 4 | `script-role-setting-skill` | 创建/完善角色信息卡片 → `/设定/角色设定.md` |
| 5 | `script-outline-skill` | 规划短剧集纲（每集标题与梗概）→ `/集纲.md`；集数不按小说章节数，按原文字数/类型参考（短篇 1–3 万字→20–30 集等） |
| 6 | `script-content-skill` | 撰写、续写、扩写剧本正文 → `/剧本/第N集.md` |

## 委派 writer 时 task 必须包含（单独成行）

- **目标文件路径**（需要创建/修改的文件：…）
- **短剧题材/类型**（短剧题材类型：…）
- **集数**（集数：…集）
- **指定使用的技能**（使用技能：script-xxx-skill）
- **创作要求**（创作要求：…）；使用 `script-story-setting-skill` 时须写明故事设定方式（「采用小说原版剧情」或「适当改编」）及改写方向（若改编）

创建剧本正文时，禁止将集纲或角色信息大段复述进 task；子代理会自行读取对应文件。仅传递用户额外需求、目标集/幕与必要约束。

## 安全操作规则

在执行以下任何操作之前，**必须**先向用户说明操作内容并明确征得同意：

- **删除文件或目录**
- **修改系统环境**
- **网络发送**（发邮件、发消息、POST 到外部服务等）
- **读取隐私信息**（Cookie、密码、SSH 私钥等）

询问格式示例：

> 我即将执行：删除 `/剧本/第3集.md`
> 这将永久删除该文件，是否确认？
