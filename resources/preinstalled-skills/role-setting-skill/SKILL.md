# 角色设定技能

---

## 角色设定文件格式规范（设定/角色设定.md）

角色设定存储在 `.{你的工作区路径}/设定/` 文件夹。该文件夹用于存储所有角色相关设定，永久存在，不得删除，名称只能是 `.{你的工作区路径}/设定/`。

角色设定文件路径固定为 `.{你的工作区路径}设定/角色设定.md`，用于存储主角信息、角色关系网（mermaid 图表）和角色表。

文件格式为 Markdown（`.md`），内容结构必须严格遵守：

```
## 主角信息
[主角基本信息（用户必须提供）]

## 角色关系网
[必须使用 mermaid 图表展示角色之间的关系网络，不要使用其他格式]

**格式：**
```mermaid
graph TB
    A[（主角名称）<br/>主角]
    B[（角色1名称）]
    C[（角色2名称）]

    A ---|角色关系| B
    A ---|角色关系| C
    D -.角色关系.- B
    ···
```

## 角色表
[主角以及其他出场人物的基本信息（角色名称（必须具体到姓名而不是角色），年龄，姓名，和其他角色的关系），能力与特质（可由AI补全）]

**格式：**

| 角色名称 | 性别 | 年龄 | 职业/身份 | 性格特点 | 能力/特质 | 与其他角色的关系 |
|---------|------|------|------|--------|----------|----------|
| （主角1） | ··· | ··· | ··· | ··· | ··· | ··· |
| （主角2） | ··· | ··· | ··· | ··· | ··· | ··· |
| （角色1） | ··· | ··· | ··· | ··· | ··· | ··· |
| （角色2） | ··· | ··· | ··· | ··· | ··· | ··· |
```

## 工作流程

### Step 1：读取其他设定文件内容

至少读取：

```
read_file(".{你的工作区路径}/设定/故事设定.md")
read_file(".{你的工作区路径}/设定/角色设定.md")   # 若已存在
```

若 `./设定/` 下有其他补充设定文件，也应一并读取并吸收约束，避免角色设定与现有世界观冲突。

### Step 2：使用思考工具判断当前小说题材类型（必须）

先根据用户输入、`./设定/故事设定.md`、上下文任务，判断当前题材类型（如世情、古言、玄幻、都市、科幻等）。

### Step 3：读取对应题材的角色设定写作指南（必须）

根据题材，从此skill的 ./role-setting-skill/角色设定写作指南 目录下读取对应指南文件：

```
./role-setting-skill/角色设定写作指南
```

若存在明确匹配的指南文件，必须先读取再创作；若无精确匹配，则读取最接近题材的指南并在输出中保持风格一致性。

### Step 4：基于设定生成或更新 `./设定/角色设定.md`

根据“角色设定文件格式规范”写入完整内容，保证：

- 主角信息来自用户输入（必填信息不可臆造）
- 角色关系网必须使用 mermaid 图表
- 角色表中的角色名称必须具体到姓名，不可写“主角/反派/师父”这类泛称
- 能力与特质可由 AI 在不冲突前提下补全

### Step 5：写后自检

写入后必须检查：

重点检查字段完整性、角色关系一致性、与故事设定的兼容性。

---

## 质量要求

- 角色必须有**内在逻辑**：性格、动机、行为三者一致
- 避免**完美主角综合征**：优点之外必须有明显弱点或局限
- **配角也要立体**：即便戏份少，也需要有自己的动机
- 档案应**服务于写作**：不必面面俱到，重点写对写作有直接指导价值的内容
