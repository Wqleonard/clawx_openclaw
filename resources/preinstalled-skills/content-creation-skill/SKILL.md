## 章节正文文件格式规范（./正文/第一章.md、./正文/第二章.md、./正文/第三章.md等）

正文存在一个 `./正文/` 文件夹对象，用于前端解析目录结构。该对象永久为空，不得编辑，名称只能是 `./正文/`。

章节正文文件必须命名为：

- `./正文/第一章.md`
- `./正文/第二章.md`
- `./正文/第三章.md`
- ...

格式要求：

1. 文件为 Markdown（`.md`），内容使用纯文本表达。
2. 文件内容为该章节的完整正文，不附加与正文无关的说明文本。
3. 正文必须依据大纲创作，存储在 `./正文/` 文件夹下。

---

## 工作流程

### Step 1：先读取设定与大纲（强制）

创作前至少读取：

```
read_file("./设定/故事设定.md")
read_file("./设定/角色设定.md")
read_file("./大纲.md")
read_file("./正文/第X章.md")     # 若为改写/续写该章
read_file("./正文/第X-1章.md")   # 承接上一章
```

说明：导语不是必须读取文件，可按需要选择是否读取。

### Step 2：读取文风指导（强制）

在完成 Step 1 后，再读取当前 skill 下的文风文件：

```
read_file("content-creation-skill/文风.md")
```

### Step 3：根据大纲与文风生成正文

生成要求：

- 严格遵循 `./大纲.md` 对应章节的剧情目标与推进顺序
- 与 `./设定/故事设定.md`、`./设定/角色设定.md` 保持一致，不擅自引入冲突设定
- 根据 `./content-creation-skill/文风.md` 的语气、节奏和表达要求写作
- 只输出章节正文内容，不添加总结、注释、工具说明

### Step 4：写入章节文件

将正文写入对应章节文件（如 `./正文/第一章.md`）：

```
write_file("./正文/第X章.md", ...)
```

若目标章节文件已存在，则按用户要求覆盖写入最新版本。

---

## 质量要求

- 正文必须可直接发布阅读，不得夹杂流程性文字
- 章节内部要有明确推进，避免空转和重复信息
- 人物行为与动机需与角色设定一致
- 语言风格需与 `./content-creation-skill/文风.md` 保持一致性
