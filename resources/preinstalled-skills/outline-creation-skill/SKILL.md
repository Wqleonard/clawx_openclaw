## 大纲文件格式规范（大纲.md）

大纲文件名只能是 `./大纲.md`，并存储在根目录下。

若用户未指定大纲长度，默认生成 10 章。

文件格式为 Markdown（`.md`），内容结构必须严格遵守：

```md
## 第一章
**章节标题：** [章节的标题]

**剧情描述：**
1. [剧情描述1，长度少于两行。其中包含剧情节奏控制（快或慢），篇幅长度控制（长或短）]
2. [剧情描述2，长度少于两行。其中包含剧情节奏控制（快或慢），篇幅长度控制（长或短）]
...

**剧情点联系：**
[和其他章节剧情点的联系，长度小于两行]

**人物动机：**
[简要描述章节中主要人物的动机和心态，长度小于两行]

**情感基调：**
[两个字描述情感基调]

**章节亮点：**
[这个章节吸引读者的具体要点。字数少于一行]

## 第二章
...
```

## 工作流程

### Step 1：读取设定相关文件

创作前必须读取已有设定，至少包括：

```
read_file("./设定/故事设定.md")
read_file("./设定/角色设定.md")
read_file("./大纲.md")   # 若已存在，用于续写或修订
```

若存在其他设定补充文件，也应一并读取，确保章节规划与设定一致。

### Step 2：使用思考工具判断当前小说类型（必须）

先根据用户输入、会话上下文与已有设定判断题材类型（如世情、悬疑、甜文、虐文、爽文、职场、复仇、穿书、重生等）。

### Step 3：读取对应题材的大纲写作指南（必须）

根据题材，从此skill的 `./outline-creation-skill/大纲写作指南` 目录下读取对应指南文件：

```
outline-creation-skill/大纲写作指南/
```

若有精确匹配，优先读取该指南；若无精确匹配，读取最接近题材的指南，并保持叙事节奏与风格一致。

### Step 4：生成并写入大纲

按“大纲文件格式规范”生成或更新 `./大纲.md`：

- 仅写入根目录文件 `./大纲.md`
- 用户未指定章节总数时，默认生成 10 章
- 每章都必须包含：章节标题、剧情描述、剧情点联系、人物动机、情感基调、章节亮点
- 章节之间要形成连续因果与明确承接关系

### Step 5：写后自检

写入后必须检查：

- 章节数量是否符合用户要求（未指定时应为 10 章）
- 每章字段是否齐全、格式是否一致
- 与 `./设定/故事设定.md`、`./设定/角色设定.md` 是否冲突

## 质量要求

- **每章必须有功能**：推进情节 / 塑造角色 / 埋设伏笔，至少满足其一
- **章节承接清晰**：每章都要与前后章形成可追踪的剧情联系
- **节奏有变化**：避免连续多章同强度推进，保持阅读起伏
- **设定一致性**：人物行为、动机、世界规则不得与设定文件冲突
