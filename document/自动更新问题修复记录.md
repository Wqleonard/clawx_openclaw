# 自动更新问题修复记录

> 本文档记录 2026-03-20 会话中对自动更新功能的完整排查与修复过程，供后续会话参考。

---

## 一、问题背景

应用使用 electron-updater + 火山引擎对象存储（TOS）实现自动更新。更新包和 yml 文件上传到 `https://story-claw.tos-cn-beijing.volces.com/latest/`。

本次会话遇到并修复了以下问题：

1. **sha512 checksum mismatch** — yml 文件中 hash 与实际文件不匹配
2. **latest-mac.yml 重复条目** — 每次打包 yml 内容累积而非覆盖
3. **Spotlight 显示三个 Helper 进程** — macOS 聚合搜索索引了 Electron Helper
4. **更新检测失败不应显示错误** — 404/网络不可达时应静默降级
5. **macOS 代码签名验证失败** — ShipIt 验证新包签名失败，更新无法安装
6. **下载完自动触发 ShipIt** — 不等用户点击就触发签名验证失败
7. **手动下载按钮无效** — URL 用了当前版本号而非新版本号
8. **点击安装后 app 卡死** — `execSync` 同步阻塞导致 UI 无响应

---

## 二、根本原因分析

### 2.1 yml 重复条目

electron-builder 打包 mac 时有 2 个 target（dmg + zip）× 2 个 arch（x64 + arm64）= 4 次打包，每次都往 `latest-mac.yml` **追加**而不是覆盖重写，导致重复。

### 2.2 sha512 mismatch

yml 里的 hash 和存储桶里的文件不一致，根本原因是 yml 重复导致 hash 错乱。

### 2.3 macOS 签名验证失败

adhoc 签名的 app，其 designated requirement 是 `cdhash H"xxx"`，每次打包 cdhash 都不同。ShipIt 用已安装版本的 cdhash requirement 验证新版本，必然失败。

报错：`Code signature at URL ... did not pass validation: 代码未能满足指定的代码要求`

### 2.4 下载完自动触发 ShipIt

`autoUpdater.autoInstallOnAppQuit = true`（默认值）导致下载完成后立即触发 `nativeUpdater.checkForUpdates()`，ShipIt 在后台验证签名，不等用户点击安装按钮。

## 三、修复内容

### 3.1 scripts/generate-update-yml.mjs

**改动**：mac 和 win 包互相独立，单独打 mac 不再报缺少 win 包的错误。

- 原来：同时要求 mac + win 包都存在才能生成 yml
- 现在：有 mac 包就生成 mac yml，有 win 包就生成 win yml，互不依赖
- 顶层 `path`/`sha512` 指向 `arm64.zip`（mac）或 `x64.exe`（win）

### 3.2 package.json

**改动**：`package:mac`、`package:mac:local`、`package:win` 命令末尾自动调用脚本覆盖 yml。

```json
"package:mac": "pnpm run package && electron-builder --mac --publish never && node scripts/generate-update-yml.mjs --output-dir release"
```

打包完成后脚本重新扫描 `release/` 目录计算真实 hash，覆盖 electron-builder 生成的重复 yml。

### 3.3 scripts/after-sign.cjs（新文件）

**作用**：electron-builder 完成所有签名后，用 identifier-based designated requirement 重签主 app bundle，替换掉 cdhash-based requirement。

```js
// 签名命令（不带 --deep，避免破坏 Electron Framework）
echo 'designated => identifier "app.storyclaw.desktop"' | \
  codesign --sign - --force --timestamp=none --options runtime --requirements - "${appPath}"
```

**注意**：
- 必须用 `afterSign` 钩子，不能用 `afterPack`（afterPack 之后 electron-builder 还会再签一次，会覆盖）
- 不能带 `--deep`，否则会破坏 Electron Framework 的 Team ID 验证，导致 app 启动崩溃（`SIGABRT: Library not loaded: Electron Framework`）
- 不能签整个 bundle（会导致 `nested code is modified or invalid`），只签主 bundle 本身

### 3.4 electron-builder.yml

**改动**：
```yaml
afterPack: ./scripts/after-pack.cjs
afterSign: ./scripts/after-sign.cjs   # 新增

mac:
  hardenedRuntime: false   # 原来是 true，没有证书不应开启
  notarize: false          # 原来是 true，没有证书不应开启
  strictVerify: false      # 新增，让 ShipIt 跳过严格验证
```

### 3.5 electron/main/updater.ts

**改动1**：`autoInstallOnAppQuit = false`

阻止下载完成后自动触发 ShipIt 验证，让用户有机会点击安装按钮。

**改动2**：`quitAndInstall()` 完全绕过 ShipIt（仅 macOS）

```
用户点击安装 → 写 shell 脚本到 temp 目录 → app.quit()
→ 脚本等进程退出后 unzip 覆盖 /Applications/StoryClaw.app
→ open 重启 app
```

脚本内容：
```sh
#!/bin/sh
while kill -0 <PID> 2>/dev/null; do sleep 0.5; done
rm -rf "/Applications/StoryClaw.app"
unzip -q -o "<zipPath>" -d "/Applications"
open "/Applications/StoryClaw.app"
```

zip 文件路径：`~/Library/Caches/storyclaw-updater/pending/StoryClaw-<version>-mac-<arch>.zip`

Windows 走原来的 `autoUpdater.quitAndInstall()`，不受影响（已配置 `verifyUpdateCodeSignature: false`）。

**改动3**：`needs-reinstall` 状态时保留 `info`（版本号）

`updateStatus` 方法改为：若新状态未显式提供 `info`，则保留已有的 `info`，确保 `needs-reinstall` 时前端仍能拿到新版本号。

**改动4**：`getManualDownloadUrl` IPC handler 用新版本号

原来用 `app.getVersion()`（当前安装版本），改为优先用 `updater.getStatus().info?.version`（待安装的新版本）。

**改动5**：签名/网络错误静默处理

- 网络/yml 不可达（404、ENOTFOUND、net:: 等）→ 静默降级为 `not-available`，不显示错误
- 签名验证失败（ShipIt cdhash mismatch）→ 设为 `needs-reinstall` 状态

### 3.6 src/stores/update.ts

**改动1**：新增 `needs-reinstall` 状态类型

**改动2**：`clearError()` 遇到 `needs-reinstall` 状态时直接 return，不重置状态（否则用户点"检查更新"会先 clearError 把状态重置为 idle，再 check 又回到 available，状态错乱）

**改动3**：`checkForUpdates()` 的 finally 兜底改为 `not-available`（原来是显示 dev mode 错误文案）

### 3.7 src/components/settings/UpdateSettings.tsx

**改动**：
- 新增 `needs-reinstall` 状态的 UI：黄色提示框 + "手动下载安装包"按钮
- `handleOpenManualDownload`：调用 `update:getManualDownloadUrl` IPC 拿到正确的新版本 dmg 链接，然后 `shell:openExternal` 打开
- `renderStatusIcon`：`needs-reinstall` 显示 `AlertTriangle` 黄色图标

### 3.8 i18n 三语言文件

新增翻译 key（zh/en/ja）：
- `updates.status.needsReinstall`
- `updates.action.downloadManually`
- `updates.reinstallHint`

### 3.9 electron/main/updater.ts — 安装卡死问题（后续修复）

**问题**：点击"安装并重启"后 app 卡死，触发系统强制退出。

**原因**：`execSync('sh script &')` 虽然用了 `&`，但 `execSync` 本身是同步阻塞调用，加上 `app.quit()` 触发 Gateway 进程关闭需要时间，期间 UI 完全无响应。

**修复**：
1. 用 `spawn(..., { detached: true, stdio: 'ignore' }).unref()` 替换 `execSync`，真正异步启动脚本不阻塞主进程
2. 先调用 `BrowserWindow.getAllWindows().forEach(win => win.hide())` 立即隐藏所有窗口，用户看到 app 消失，体验流畅
3. `setTimeout(() => app.quit(), 300)` 给隐藏动画留 300ms 后再退出

**最终 quitAndInstall 流程（macOS）**：
```
用户点击安装
  → 立即隐藏所有窗口（用户感知 app 已关闭）
  → spawn 异步启动 shell 脚本（不阻塞）
  → 300ms 后 app.quit()
  → 脚本等待进程退出 → unzip 覆盖 /Applications/StoryClaw.app → open 重启
```

## 四、上传存储桶规范

每次打包后需上传到 `https://story-claw.tos-cn-beijing.volces.com/latest/` 的文件：

| 文件 | 说明 |
|------|------|
| `StoryClaw-<ver>-mac-arm64.zip` | mac arm64 更新包 |
| `StoryClaw-<ver>-mac-x64.zip` | mac x64 更新包 |
| `StoryClaw-<ver>-mac-arm64.dmg` | mac arm64 安装包 |
| `StoryClaw-<ver>-mac-x64.dmg` | mac x64 安装包 |
| `StoryClaw-<ver>-mac-arm64.zip.blockmap` | 差量更新索引（必须上传） |
| `StoryClaw-<ver>-mac-x64.zip.blockmap` | 差量更新索引（必须上传） |
| `latest-mac.yml` | mac 更新描述文件 |
| `StoryClaw-<ver>-win-x64.exe` | win x64 安装包 |
| `StoryClaw-<ver>-win-arm64.exe` | win arm64 安装包 |
| `latest.yml` | win 更新描述文件 |

**注意**：`.blockmap` 文件必须上传，否则差量下载失败会回退全量下载（功能正常但多下载一次）。

## 五、打包流程

```bash
# 打 mac 包
pnpm package:mac
# 打包完成后 release/ 下会自动生成正确的 latest-mac.yml（无重复条目）
# 打包日志中应看到：
# [after-sign] ✅ Re-signed StoryClaw.app with identifier requirement: app.storyclaw.desktop

# 打 win 包（在 Windows 机器上）
pnpm package:win
```

## 六、验证方法

1. 打 0.2.6 包，安装 dmg
2. 验证签名：`codesign -d --requirements - /Applications/StoryClaw.app`
   - 应输出：`designated => identifier "app.storyclaw.desktop"`
   - 不应出现：`cdhash H"xxx"`
3. 打 0.2.7 包，上传到存储桶
4. 打开 0.2.6 检查更新，下载完成后点"安装并重启"
5. app 退出，几秒后自动重启为 0.2.7
6. 应用日志中应看到：`[Updater] Bypassing ShipIt — direct install from ...`

## 七、已知限制

- macOS 绕过 ShipIt 的方案依赖 `~/Library/Caches/storyclaw-updater/pending/` 目录下的 zip 文件，该路径由 electron-updater 内部决定，如果 electron-updater 版本升级改变了缓存路径，需要同步更新 `quitAndInstall()` 中的路径逻辑
- `afterSign` 钩子的重签名目前只改变 designated requirement，不影响实际签名内容，`codesign --verify` 会报 warning，但 app 可以正常运行
- Win 更新依赖 `verifyUpdateCodeSignature: false` 配置，如果未来需要代码签名，需要移除该配置并配置证书
