# BoomClaw 文件系统实行方案

> 目标：在现有 Electron + React 架构上，实现类 Cursor 的文件系统面板，与 Agent 会话深度结合，支持读写删改文件，并与已有富文本编辑器（Tiptap）联动。用户可用它写小说、管理文稿，AI 可直接操作文件。

---

## 一、整体架构设计

```
React Renderer（文件树面板 + 编辑器 + 聊天区）
    │
    │  window.electronAPI.fs.*（contextBridge）
    ▼
Electron Preload（IPC 桥）
    │
    │  ipcRenderer.invoke('fs:*')
    ▼
Electron Main（fs IPC handler）
    │
    │  Node.js fs/path/chokidar
    ▼
本地文件系统（用户选择的工作目录）
```

**三栏布局（最终形态）：**

```
┌──────────┬──────────────────┬──────────────────┐
│ 文件树   │   富文本编辑器   │    聊天区        │
│ (200px)  │   (可拖拽调宽)   │   (剩余宽度)     │
│          │   TiptapEditor   │   ChatMessage    │
│ 文件夹   │                  │   ChatInput      │
│ 文件列表 │                  │                  │
└──────────┴──────────────────┴──────────────────┘
```

当前已有：编辑器 + 聊天区两栏。本方案在左侧新增文件树面板。

## 二、IPC 通道设计（electron/main → preload → renderer）

### 2.1 需要新增的 IPC 通道

| 通道名 | 方向 | 说明 |
|--------|------|------|
| `fs:open-folder` | invoke | 打开系统文件夹选择对话框，返回选中路径 |
| `fs:read-tree` | invoke | 读取目录树（递归，返回 JSON 树结构） |
| `fs:read-file` | invoke | 读取文件内容（返回 string） |
| `fs:write-file` | invoke | 写入文件内容 |
| `fs:create-file` | invoke | 新建文件 |
| `fs:create-folder` | invoke | 新建文件夹 |
| `fs:rename` | invoke | 重命名文件/文件夹 |
| `fs:delete` | invoke | 删除文件/文件夹（移入回收站） |
| `fs:move` | invoke | 移动文件/文件夹 |
| `fs:watch-start` | invoke | 开始监听目录变化（chokidar） |
| `fs:watch-stop` | invoke | 停止监听 |
| `fs:changed` | main→renderer push | 文件变化事件（新增/修改/删除） |

### 2.2 OpenClaw Agent 工具扩展

在 OpenClaw Gateway 的 agent 配置中，注入以下工具（通过 agent 的 system prompt 或 tool 定义）：

| 工具名 | 说明 |
|--------|------|
| `read_file` | 读取指定路径文件内容 |
| `write_file` | 写入/覆盖文件内容 |
| `create_file` | 新建文件 |
| `list_directory` | 列出目录内容 |
| `delete_file` | 删除文件 |
| `search_files` | 在工作目录内搜索文件名或内容 |

这些工具通过 IPC 调用 `fs:*` 通道，Agent 操作文件 = 调用 IPC = 操作本地文件系统。

## 三、分步实施计划

### Step 1：Electron 主进程 — fs IPC handler

**新建文件：** `electron/services/filesystem/index.ts`

```typescript
// 核心职责：
// 1. 注册所有 fs:* ipcMain.handle
// 2. 封装 Node.js fs/promises 操作
// 3. 管理 chokidar watcher 实例
// 4. 向 renderer 推送 fs:changed 事件

import { ipcMain, dialog, BrowserWindow, shell } from 'electron'
import fs from 'fs/promises'
import path from 'path'
import chokidar, { FSWatcher } from 'chokidar'

let watcher: FSWatcher | null = null

export function registerFsHandlers(win: BrowserWindow) {
  // fs:open-folder
  ipcMain.handle('fs:open-folder', async () => {
    const result = await dialog.showOpenDialog(win, {
      properties: ['openDirectory']
    })
    return result.canceled ? null : result.filePaths[0]
  })

  // fs:read-tree
  ipcMain.handle('fs:read-tree', async (_, dirPath: string) => {
    return readTree(dirPath)
  })

  // fs:read-file
  ipcMain.handle('fs:read-file', async (_, filePath: string) => {
    return fs.readFile(filePath, 'utf-8')
  })

  // fs:write-file
  ipcMain.handle('fs:write-file', async (_, filePath: string, content: string) => {
    await fs.writeFile(filePath, content, 'utf-8')
    return true
  })

  // fs:create-file
  ipcMain.handle('fs:create-file', async (_, filePath: string) => {
    await fs.writeFile(filePath, '', 'utf-8')
    return true
  })

  // fs:create-folder
  ipcMain.handle('fs:create-folder', async (_, dirPath: string) => {
    await fs.mkdir(dirPath, { recursive: true })
    return true
  })

  // fs:rename
  ipcMain.handle('fs:rename', async (_, oldPath: string, newPath: string) => {
    await fs.rename(oldPath, newPath)
    return true
  })

  // fs:delete（移入回收站，安全）
  ipcMain.handle('fs:delete', async (_, targetPath: string) => {
    await shell.trashItem(targetPath)
    return true
  })

  // fs:watch-start
  ipcMain.handle('fs:watch-start', async (_, dirPath: string) => {
    if (watcher) await watcher.close()
    watcher = chokidar.watch(dirPath, {
      ignored: /(^|[\/\\])\../, // 忽略隐藏文件
      persistent: true,
      ignoreInitial: true,
      depth: 10
    })
    watcher.on('all', (event, filePath) => {
      win.webContents.send('fs:changed', { event, path: filePath })
    })
    return true
  })

  // fs:watch-stop
  ipcMain.handle('fs:watch-stop', async () => {
    if (watcher) {
      await watcher.close()
      watcher = null
    }
    return true
  })
}

// 递归读取目录树
async function readTree(dirPath: string, depth = 0): Promise<FileNode> {
  const stat = await fs.stat(dirPath)
  const name = path.basename(dirPath)
  if (!stat.isDirectory() || depth > 8) {
    return { name, path: dirPath, type: 'file' }
  }
  const entries = await fs.readdir(dirPath, { withFileTypes: true })
  const children = await Promise.all(
    entries
      .filter(e => !e.name.startsWith('.'))
      .sort((a, b) => {
        // 文件夹排前面
        if (a.isDirectory() && !b.isDirectory()) return -1
        if (!a.isDirectory() && b.isDirectory()) return 1
        return a.name.localeCompare(b.name)
      })
      .map(e => readTree(path.join(dirPath, e.name), depth + 1))
  )
  return { name, path: dirPath, type: 'folder', children }
}
```

### Step 3：前端 Store — useFileSystemStore

**新建文件：** `src/stores/filesystem.ts`

```typescript
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

export interface FileNode {
  name: string
  path: string
  type: 'file' | 'folder'
  children?: FileNode[]
}

interface FileSystemStore {
  // 状态
  workspacePath: string | null       // 当前工作目录
  tree: FileNode | null              // 目录树
  openFiles: string[]                // 已打开的文件路径列表（tab）
  activeFile: string | null          // 当前激活文件路径
  fileContents: Record<string, string> // 文件内容缓存
  dirtyFiles: Set<string>            // 有未保存修改的文件

  // 操作
  openFolder: () => Promise<void>
  setWorkspace: (path: string) => Promise<void>
  refreshTree: () => Promise<void>
  openFile: (filePath: string) => Promise<void>
  closeFile: (filePath: string) => void
  saveFile: (filePath: string, content: string) => Promise<void>
  createFile: (dirPath: string, name: string) => Promise<void>
  createFolder: (dirPath: string, name: string) => Promise<void>
  renameNode: (oldPath: string, newName: string) => Promise<void>
  deleteNode: (targetPath: string) => Promise<void>
  handleFsChange: (event: string, changedPath: string) => void
}

export const useFileSystemStore = create<FileSystemStore>()(
  persist(
    (set, get) => ({
      workspacePath: null,
      tree: null,
      openFiles: [],
      activeFile: null,
      fileContents: {},
      dirtyFiles: new Set(),

      openFolder: async () => {
        const path = await window.electronAPI.fs.openFolder()
        if (path) await get().setWorkspace(path)
      },

      setWorkspace: async (path) => {
        set({ workspacePath: path, openFiles: [], activeFile: null, fileContents: {} })
        await get().refreshTree()
        await window.electronAPI.fs.watchStart(path)
      },

      refreshTree: async () => {
        const { workspacePath } = get()
        if (!workspacePath) return
        const tree = await window.electronAPI.fs.readTree(workspacePath)
        set({ tree })
      },

      openFile: async (filePath) => {
        const { openFiles, fileContents } = get()
        if (!fileContents[filePath]) {
          const content = await window.electronAPI.fs.readFile(filePath)
          set(s => ({ fileContents: { ...s.fileContents, [filePath]: content } }))
        }
        if (!openFiles.includes(filePath)) {
          set(s => ({ openFiles: [...s.openFiles, filePath] }))
        }
        set({ activeFile: filePath })
      },

      closeFile: (filePath) => {
        set(s => {
          const openFiles = s.openFiles.filter(f => f !== filePath)
          const activeFile = s.activeFile === filePath
            ? (openFiles[openFiles.length - 1] ?? null)
            : s.activeFile
          const fileContents = { ...s.fileContents }
          delete fileContents[filePath]
          return { openFiles, activeFile, fileContents }
        })
      },

      saveFile: async (filePath, content) => {
        await window.electronAPI.fs.writeFile(filePath, content)
        set(s => {
          const dirty = new Set(s.dirtyFiles)
          dirty.delete(filePath)
          return {
            fileContents: { ...s.fileContents, [filePath]: content },
            dirtyFiles: dirty
          }
        })
      },

      createFile: async (dirPath, name) => {
        const path = `${dirPath}/${name}`
        await window.electronAPI.fs.createFile(path)
        await get().refreshTree()
        await get().openFile(path)
      },

      createFolder: async (dirPath, name) => {
        await window.electronAPI.fs.createFolder(`${dirPath}/${name}`)
        await get().refreshTree()
      },

      renameNode: async (oldPath, newName) => {
        const dir = oldPath.substring(0, oldPath.lastIndexOf('/'))
        const newPath = `${dir}/${newName}`
        await window.electronAPI.fs.rename(oldPath, newPath)
        await get().refreshTree()
      },

      deleteNode: async (targetPath) => {
        await window.electronAPI.fs.delete(targetPath)
        set(s => ({
          openFiles: s.openFiles.filter(f => f !== targetPath),
          activeFile: s.activeFile === targetPath ? null : s.activeFile
        }))
        await get().refreshTree()
      },

      handleFsChange: (event, changedPath) => {
        // 文件变化时刷新树，如果是当前打开的文件则重新读取
        get().refreshTree()
        const { activeFile, openFiles } = get()
        if (openFiles.includes(changedPath) && event === 'change') {
          window.electronAPI.fs.readFile(changedPath).then(content => {
            set(s => ({ fileContents: { ...s.fileContents, [changedPath]: content } }))
          })
        }
      }
    }),
    {
      name: 'filesystem-store',
      partialize: (s) => ({ workspacePath: s.workspacePath }) // 只持久化工作目录
    }
  )
)
```

### Step 5：聊天页集成 — 四栏变三栏

**修改文件：** `src/pages/Chat/index.tsx`

当前布局：`[编辑器] | [聊天区]`（两栏）

改为：`[文件树] | [编辑器] | [聊天区]`（三栏）

关键改动：
1. 引入 `useFileSystemStore`
2. 左侧新增文件树面板（固定 220px，可折叠）
3. 编辑器内容与 `activeFile` 联动：
   - 切换文件 → 编辑器加载对应内容
   - 编辑器内容变化 → 标记 dirty
   - Ctrl+S / Cmd+S → 保存当前文件
4. 监听 `fs:changed` 事件

```typescript
// 新增状态
const { tree, activeFile, fileContents, openFile, saveFile } = useFileSystemStore()
const [fileTreeOpen, setFileTreeOpen] = useState(true)
const FILE_TREE_WIDTH = 220

// 编辑器内容与 activeFile 联动
useEffect(() => {
  if (activeFile && fileContents[activeFile] !== undefined) {
    setEditorContent(fileContents[activeFile])
  }
}, [activeFile])

// 编辑器变化时标记 dirty（不立即保存）
const handleEditorChange = (content: string) => {
  setEditorContent(content)
  if (activeFile) {
    useFileSystemStore.getState().dirtyFiles.add(activeFile)
  }
}

// 键盘快捷键保存
useEffect(() => {
  const handleKeyDown = (e: KeyboardEvent) => {
    if ((e.metaKey || e.ctrlKey) && e.key === 's') {
      e.preventDefault()
      if (activeFile) saveFile(activeFile, editorContent)
    }
  }
  window.addEventListener('keydown', handleKeyDown)
  return () => window.removeEventListener('keydown', handleKeyDown)
}, [activeFile, editorContent, saveFile])

// 监听文件系统变化
useEffect(() => {
  const cleanup = window.electronAPI.fs.onChanged(({ event, path }) => {
    useFileSystemStore.getState().handleFsChange(event, path)
  })
  return cleanup
}, [])
```

## 六、注意事项

1. **安全**：`fs:read-file` / `fs:write-file` 只允许操作用户选择的工作目录内的路径，主进程需做路径校验（`path.resolve(filePath).startsWith(workspacePath)`），防止路径穿越。

2. **chokidar 依赖**：需要 `pnpm add chokidar`，它已是 Electron 生态常用库，无兼容问题。

3. **大文件**：读取超过 5MB 的文件时，编辑器可能卡顿。可在 `fs:read-file` 中加大小限制，超限时提示用户。

4. **编辑器与文件联动**：切换文件时，当前文件如果有未保存修改（dirty），需提示用户是否保存，避免丢失内容。

5. **Windows 路径**：Windows 路径分隔符是 `\`，拼接路径时统一用 `path.join()` 而非字符串拼接。

6. **持久化**：只持久化 `workspacePath`，重启后自动恢复上次工作目录。文件内容不持久化（每次从磁盘读取）。

#### 8.2 文件系统 Skill 的两种注入方式

**方式 A：写作上下文注入（推荐，无需改 Gateway）**

用户在文件树右键选中文件 → "添加到 Agent 上下文" → 文件内容写入 OpenClaw 的 context 目录 → Agent 对话时自动感知文件内容。

```
实现路径：
1. 新增 IPC 通道 fs:add-to-context
2. 主进程将文件内容写入 ~/.openclaw/agents/{agentId}/context/{filename}
3. OpenClaw 的 context 加载机制自动读取（已有，无需改 Gateway）
4. 文件树节点右键菜单新增"添加到上下文" / "从上下文移除"
5. store 中维护 contextFiles: string[] 状态，高亮已添加的文件
```

写小说场景举例：
```
用户右键《人物设定.md》→ 添加到上下文
用户右键《大纲.md》→ 添加到上下文
用户在聊天区说："帮我续写第三章"
Agent 已感知人物设定和大纲，直接生成符合设定的内容
Agent 调用 write_file 写入《第三章.md》
文件树自动刷新，编辑器打开新文件
```

**方式 B：注册写作专用 Skill（完整方案，需要 Skill 文件）**

在 `~/.openclaw/skills/` 下注册自定义 skill，让 Agent 拥有文件操作能力作为 tool。

新建文件：`resources/skills/boomclaw-writer/`（打包时内置）

```yaml
# resources/skills/boomclaw-writer/skill.yaml
name: BoomClaw Writer
slug: boomclaw-writer
description: 写作助手技能，支持读写工作区文件、管理章节结构
version: 1.0.0
emoji: ✍️
tools:
  - name: read_file
    description: 读取工作区文件内容
    handler: ipc://fs:read-file
  - name: write_file
    description: 写入或更新工作区文件
    handler: ipc://fs:write-file
  - name: list_directory
    description: 列出目录内容
    handler: ipc://fs:read-tree
  - name: create_file
    description: 新建文件
    handler: ipc://fs:create-file
```

安装逻辑（应用启动时自动安装）：

```typescript
// electron/services/filesystem/install-writer-skill.ts
import path from 'path'
import fs from 'fs/promises'
import { app } from 'electron'

export async function installWriterSkill(skillsDir: string) {
  const src = path.join(app.getAppPath(), 'resources/skills/boomclaw-writer')
  const dest = path.join(skillsDir, 'boomclaw-writer')
  // 如果已存在且版本一致则跳过
  try {
    await fs.access(dest)
    return // 已安装
  } catch {
    await fs.cp(src, dest, { recursive: true })
  }
}
```

#### 8.7 三种 Agent 打通策略总结

| 策略 | 适用场景 | 实现复杂度 | 推荐度 |
|------|---------|-----------|--------|
