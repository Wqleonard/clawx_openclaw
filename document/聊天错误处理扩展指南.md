# 聊天错误处理扩展指南

本文档说明 `runtime-event-error` 场景下，前端如何从网关事件里提取并展示错误文案，以及后续新增错误码时的扩展方式。

## 当前行为

文件：`src/stores/chat.ts`

在 `handleChatEvent -> case 'error'` 中，错误文案由 `resolveRuntimeErrorMessage(event)` 统一解析。

优先级规则：

1. 当 `status===402` 或 `code===402` 时，优先使用 `detail/details` 中的报错信息；
2. 其他情况按通用优先级回退：
   - `details / detail`
   - `details.error`
   - `event.errorMessage`
   - `event.error`
   - `event.message`
   - 默认 `'An error occurred'`

`normalizeErrorText()` 会尝试从以下字段提取可读文案：

- `message`
- `error`
- `detail`
- `reason`
- `msg`
- `errorMessage`
- `error_message`

如果是对象且没有明确字段，会尝试 `JSON.stringify` 作为兜底，避免展示 `[object Object]`。

## 后续新增错误码处理（推荐方式）

在 `src/stores/chat.ts` 的 `resolveRuntimeErrorMessage()` 内新增分支：

```ts
// Extend here for future code/status-specific UX behavior.
if (status === 429 || code === 429) {
  return '请求过于频繁，请稍后重试。';
}
```

建议顺序：

1. 先判断 `status/code`；
2. 优先取 `details` 内业务文案；
3. 再回退到通用文案字段；
4. 最后兜底默认文案。

## 建议的错误码约定

后端返回时建议尽量统一以下结构，前端解析最稳：

```json
{
  "state": "error",
  "errorMessage": "fallback message",
  "status": 402,
  "code": 402,
  "details": {
    "message": "余额不足，请充值后重试"
  }
}
```

如果后端无法统一字段，请至少保证 `details.message` 可用，前端会优先展示该值。
